# スケジュール・成果物

## 14. スケジュール
期限は **1週間(2026-11-08〜11-15)**。範囲は F-01〜F-09(Must)とデモ環境へのデプロイ。

| 日 | 内容 | 機能 |
|---|---|---|
| 1日目 11/8〜9 | 要件定義書の確定、環境構築(Next.js の雛形、Prisma・Better Auth、docker-compose、CI) | — |
| 2日目 | 認証(登録・ログイン・ログアウト、ヘッダー、ログインが必要な画面の保護) | F-01, F-02 |
| 3日目 | レシピの投稿・編集・削除(材料・手順の行の追加・削除・並び替え、権限チェック) | F-03, F-04 |
| 4日目 | 一覧・詳細・検索(キーワード・カテゴリ・調理時間、URL クエリ、もっと見る) | F-05, F-06, F-07 |
| 5日目 | お気に入り、完成写真 | F-08, F-09 |
| 6日目 | デプロイ(Vercel + Supabase)、E2E での通し確認、サンプルレシピの投入、不具合修正 | — |
| 7日目 11/15 | 予備日。余裕があれば v1.1(人気順 → ユーザーページ → コメント の順)、README の仕上げ | — |

- 機能ごとに Issue を作り、Issue → 作業ブランチ → Pull Request の流れで進める(`CLAUDE.md` 参照)。
- 1週間のため、独立した設計書は作らない。画面・Server Actions・テーブルの設計は、各機能の Issue と Pull Request の説明に書く。
- 予定より遅れた場合は、7日目の予備日を使う。それでも足りなければ、受け入れ基準のうち見た目に関わるもの(代わりの画像、最終更新日の表示など)を後回しにし、データが正しく扱えることを優先する。
